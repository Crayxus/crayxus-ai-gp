测试环境（缺一样就在备注里写明）

电脑 A
全新 Windows 11（新装系统或新账户，从没装过 Arduino IDE、驱动、EI TOKEN）。Chrome 或 Edge 最新版。能上网。
账号
A 节用自己的邮箱新注册（测注册流程）。其余各节用内部测试账号 test1@eitoken.ai / test2@eitoken.ai，密码都是 123456：额度无限，握手功能只对这两个账号开放。
板子
本轮只测四类（首批机构用的）：Arduino Uno、Arduino Nano（旧 bootloader 版）· ESP32 DevKit（CH340 或 CP2102）、ESP32-S3 DevKitC · 树莓派 4 或 5（烧好官方系统的 SD 卡）· 地瓜 RDK X5（烧好官方系统）· 一块 USB-TTL 小板（CH340，接树莓派调试口用）· 机构用的 Arduino 套件（mBot 或传感器套件，有就带上）
元件
LED + 220Ω · 按键 · SG90 舵机 · DHT22 · 超声波 HC-SR04 · 0.96 寸 OLED · 杜邦线 · 面包板 · USB 摄像头（RDK / 树莓派视觉演示）
树莓派准备
SD 卡 boot 分区的 config.txt 末尾加一行 enable_uart=1；USB-TTL 接 GPIO14(TX)→RX、GPIO15(RX)→TX、GND（Pi 5 可直接用板上 3 针调试口）。记下登录用户名和密码。
RDK 准备
找到调试串口（板载调试 USB 口或调试针），记下登录用户名和密码。
数据线
确认是数据线不是充电线：先在手机上试能传文件。带一根已知坏的充电线做异常测试。

记录规则

  • 每条都做，不跳步骤。做不了的选「跳过」并写原因。
  • 失败必须附：截图 + 页面上「原始输出」展开后的文字 + 你当时插的是什么板、什么线。
  • P0 交付必须全过 · P1 允许有已知问题但要记录 · P2 锦上添花。
  • 凡是页面说"会复位板子一次"的操作，板子灯闪一下、串口断一下都是正常，不算失败。
  • 凡是提示"浏览器不允许…""要 Windows 版"这类如实的限制说明，出现了就算通过——我们要验证的是它说清楚了，不是它能突破浏览器。
安全：接舵机、电机、继电器时电源单独接；GPIO 点灯时 LED 必须串 220Ω 电阻，别把 5V 接到树莓派 / RDK 的 GPIO 上。

终交付判定

  • A、B、C、E、H 五节的 P0 全部通过，且 G 节异常路径每条都有清楚的提示（不是白屏、不是英文报错）。
  • 任一 P0 失败 → 不交付，把失败条目连截图发回。
  • P1 失败超过 3 条 → 不交付。
  • 做完把「复制结果」的文本发回，附截图文件夹。
