EI TOKEN · 硬件

EI HUB —— 桌面供电与接入枢纽

一头接电、一头接电脑，把主流开发板全部供上电、接进 EI TOKEN；按屏顶的 ◀ ▶ 两个键选板子，电压和限流自动配好。有线台式，不带电池。

1先把几件事定下来

决定结论为什么
形态板子有座位的托盘：220×120×22mm 的石墨蓝矮板，顶面四个浅凹槽是"座位"，ESP32 / Arduino / Black Pill 躺进去，USB-A 口开在座位后壁，线只有 5cm；每个座位一圈细光线（青=待机、白=烧录中、红=过流）。后沿一道 60mm 高的铝合金窄脊，嵌一块 2.4 寸竖屏当脸，眼睛看向正在烧录的座位；脊两端各一个圆按钮（◀ ▶ 切板子，长按确认）。大板子（树莓派 / Jetson）从脊背面的口接桌上就是"一个小工位，四块板各就各位"，和 eitoken.ai 设备页四张卡一一对应——网页上哪张卡亮，桌上哪个座位亮。这是别人抄不走的形态
电从哪来USB-C PD 100W 适配器（随机附 GaN 头）；不做内置电池Jetson 一开机就要 20-40W，电池版撑不了几分钟还贵一倍；台式用不着
怎么接电脑一根 USB-C 数据线；HUB 内置 4 口 USB 2.0 集线器，MCU 口既供电又走数据板子插 HUB 就等于插电脑，eitoken.ai 直接认、直接烧
「选芯片自动适配」怎么实现◀ ▶ 两键切档（ESP32 / Arduino / STM32 / 树莓派 / Jetson / 小车 / 自定义）→ 决定 DC 口电压、每口限流、辅助引脚行为；eitoken.ai 认出板子后也能通过 USB 告诉 HUB 切档HUB 自己看不到下游 USB 枚举（它不是主机），所以"自动"由网页端下发，本地两个按钮兜底
一个独有卖点HUB 上带一组 UART + BOOT0 + NRST 三针口，由 HUB 的 MCU 控制STM32 初始化在 Windows 纯网页做不了（DFU 没驱动），接 HUB 就能做——HUB 替用户拨 BOOT0、按复位，走串口 bootloader
暂不做24V 工业、PoE、无线充、电池、USB 3.0 高速口不主流，或者成本翻倍

2接口与供电能力（覆盖主流）

口规格给谁用保护
USB-A × 45V / 每口 3A，走数据（经内置 HUB 到电脑）ESP32 全系、Arduino Uno / Nano / Mega、STM32 Blue Pill / Black Pill、CH340 类一切串口板、StackChan每口独立 eFuse 限流 + 电流表 + 短路自恢复
USB-C 供电口 × 15V / 5A（PD 通告 5V5A）树莓派 4 / 5、RDK X5同上；树莓派 5 要 5A 才不限制外设
DC 5.5×2.5 × 1可切 12V / 4A 或 19V / 3A（切到 Jetson 或 小车档决定）Jetson Orin Nano（9–20V）、Jetson Nano（5V4A 用 A 口不够，走 DC 5V 档）、ROS 小车 12V 底盘输出前有开关，换档时先断电再切，防止 19V 打到 12V 设备
3 针辅助口 × 1TX / RX / GND + BOOT0 / NRST（5 针排母，3.3V 电平）STM32 初始化、任何板子的调试串口（RDK 调试针、树莓派 GPIO 串口）HUB 的 MCU 做 USB-TTL，BOOT0 / NRST 由它拉

功率预算：20V×5A = 100W。同时接满：4 个 A 口 5V×3A 最多 60W + C 口 25W + DC 口 48W 会超。固件按档限总功率——切到 Jetson 档时 A 口总限 30W，屏上显示还剩多少。实际用户很少同时插满。

3架构

适配器 ──USB-C PD 20V──▶ [PD 协议芯片 CH224K] ──20V 母线──┬─▶ [同步降压 5V/12A] ──┬─▶ eFuse ×4 ──▶ USB-A ×4 ──▶ [USB2.0 集线器 GL852G] ──▶ 上行 USB-C ──▶ 电脑 │ └─▶ eFuse ──▶ USB-C 5V5A（树莓派） ├─▶ [降压 12V/5A] ─┐ └─▶ 20V 直通(降 19V)─┴─▶ [继电器/MOS 选一路] ──▶ DC 5.5 口 [ESP32-S3 主控] ── I²C ──▶ INA3221 ×2（6 路电流电压） ── GPIO ─▶ 各口 eFuse 使能、DC 档位、BOOT0 / NRST ── UART ─▶ 3 针辅助口（USB-TTL 功能，经集线器上电脑） ── SPI ─▶ 2.8 寸横屏（脸）；头顶 ◀ ▶ 两个按钮（GPIO） ── USB ─▶ 作为一个 CDC 设备挂在集线器上，和 eitoken.ai 说话（报电流、收切档命令）

固件（ESP32-S3，Arduino 或 ESP-IDF）

  • 档位表：每档 = { DC 电压, 各口限流, 总功率上限, 辅助口行为 }
  • 200ms 一轮读 6 路电流；超限先关那一口再报警；短路 eFuse 硬件自断
  • CDC 协议一行一条：HUB? 报型号和各口状态 · MODE jetson 切档 · BOOT0 1 / RESET 辅助口 · PORT 3 off
  • 脸：待机时一对眼睛（眨眼、看向刚插入的那个口的方向）；插板后眼睛变成板子图标 + 板名 + 电流；过流时皱眉 + 光带变红；切档时表情"确认？"，长按点头。切档要长按确认，DC 口先断电再切

EI TOKEN 端

  • 认 HUB 的 VID/PID → 设备页出一张 HUB 卡，显示各口在线和电流
  • 识别出板子家族后自动下发 MODE；「STM32 初始化」页检测到 HUB 就走辅助口，用户什么都不用拨

7和 EI TOKEN 怎么"完美适配"

原则：HUB 不是另一套软件，它是 eitoken.ai 的一只手。网页管"认板子、编译、烧录"，HUB 管"供电、拨引脚、给反馈"，两边靠一条 USB 串口协议说话。

① HUB 在电脑上是什么

  • 插上电脑，HUB 自己是一个 USB 串口设备（VID 0x303A，我们自己的 PID），下面挂着一个 4 口集线器。Windows / Mac 免驱，浏览器 Web Serial 直接开。
  • eitoken.ai 设备页多一张 HUB 卡：六个口的在线状态、每口电流、当前档位、总功率；这张卡是"桌面全景"，所有板子卡片挂在它下面。

② 板子插进 HUB 之后发生什么（用户视角）

用户动作HUBeitoken.ai
把 ESP32 插进 A2 口眼睛看向 A2 口方向，报 PORT A2 on 0.12A浏览器收到新串口，自动识别（USB 指纹 → 握手），设备页出 ESP32 卡，卡上标"HUB · A2"
—收到 MODE esp32，A2 口限流 1.5A，脸变成 ESP32 图标识别完立刻下发 MODE；用户什么都没按
点「烧录」眼睛"专注"表情，光带流动；万一过流立刻关口并报 ERR A2 overcurrent正常 Web Serial 烧录；收到 ERR 就中止并显示"HUB 报 A2 口过流，检查接线"
插一块空的 Black Pill—网页发现是 STM32 但不在 bootloader：提示"接到 HUB 的辅助口做初始化"
用 5 针线接辅助口，点「初始化」BOOT0 1 → RESET → 转发串口 → 写完 BOOT0 0 → RESET整片备份、写 EITBL、校验——全在浏览器里，Windows 纯网页也能做（这就是 HUB 绕过 DFU 那堵墙的方式）
插 Jetson 到 DC 口脸上问"Jetson 19V？"，等长按确认才通电网页同时弹同样的确认；任一边确认都行

③ 协议（USB 串口，一行一条，和 EITBL 一个风格）

HUB?                 → HUB 1 ports=A1,A2,A3,A4,C1,DC,AUX mode=esp32 power=23.4W
STAT                 → A1 on 0.12A · A2 off · … · DC 19V 1.8A
MODE jetson          → OK（DC 口先断电，切 19V，再通电）
PORT A3 off / on     → OK
AUX BOOT0 1 · AUX RESET · AUX BAUD 115200 → 辅助口成 USB-TTL，串口数据透传
FACE flash / idle / err                     → 网页也能指挥表情（烧录时"专注"，成功时"眨眼"）
事件（HUB 主动发）：EVT plug A2 · EVT unplug A2 · EVT overcurrent A2 · EVT button left

④ 软件侧要改什么（都在 1.0 已有的骨架上）

  • core/webserial.js：USB_DB 加 HUB 的 VID/PID → 家族 hub；识别时 HUB? 一句认出
  • 新增 core/hub.js：协议客户端 + 事件流；设备页 HUB 卡；板子卡片按 HUB 的 plug 事件标口位
  • 识别完成后的一处钩子：有 HUB 在线就下发 MODE；烧录前订阅 EVT overcurrent
  • 「STM32 初始化」页多一条路："经 HUB 辅助口"——把现有串口 bootloader 那套代码的 BOOT0/RESET 动作换成 AUX 命令即可
  • 桥接（Windows 版）同样一套，COM 口走 /api/serial/*

约 600 行网页代码 + HUB 固件里的协议实现。协议先定下来，固件和网页可以两头同时开工，用一个 ESP32-S3 DevKit 就能先把"网页 ↔ HUB 对话"跑通，不用等板子。
